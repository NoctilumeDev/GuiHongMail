# M2 邮箱核心与可用前端施工合同 1.0

本阶段只具体化 M0 的 A06 与 A07，不修改 M0 的邮件事实、权限、资源或服务所有权。M2 实际开工 `2026-10-13T12:12:07.6892618Z`，起始 main `f2cd29d6f5943a4025a877b145226a4460338c68`。本合同在首次产品观察前封存；每次候选运行另行绑定干净源码、构建收据、迁移摘要、浏览器版本、具名账户和数据集。

M2 的上限是“Mailbox 拥有的真实邮箱功能与可用网页”。它不产生 SMTP 接受、下一跳投递或互联网可送达结论。发送按钮在 M3 具备 SendIntent、Outbox、Delivery 与 SMTP 责任链前不得用乐观成功冒充发送；M2 写信能力以持久草稿、附件、回复和转发草稿为退出范围。

## 固定产品分母

### 邮箱事实

- 至少两个真实账户。`MessageContent` 保存不可变的原始 MIME 摘要、安全展示投影和附件元数据；`MailboxEntry` 按账户独立拥有目录、已读、主分类和删除状态。A 的读取、搜索、下载或状态修改都不能发现 B 的专有成员视图或附件能力。
- 系统目录固定为 `INBOX`、`SENT`、`ARCHIVE`、`SPAM`、`TRASH`；草稿是独立可变事实。七个用户入口固定为写信、收件箱、已发邮件、草稿箱、归档、垃圾邮件、已删除；“我的分类”只展示用户自行创建的分类，不预置类目。
- 草稿使用服务端单调版本。创建、读取、更新、重启恢复、冲突返回当前版本均须真实落库；同一账户的标题、纯文本/HTML 正文、To/CC/BCC 和附件引用属于同一草稿。回复、全部回复与转发从授权的源邮件建立新草稿，不改写源邮件。
- M2 附件单文件和总量受 M1 尺寸合同约束，文件名只作展示元数据；对象先完整写入并核对 hash/size，再由数据库事实引用。附件下载重新校验账户成员资格，使用安全内容类型与 `Content-Disposition: attachment`。
- 原始 MIME 不因展示解析而改写。解析最多 5 MiB、20 parts、8 层 multipart；未知/危险内容进入明确受限投影。HTML 展示必须删除脚本、事件属性、危险 URL、表单、嵌入内容和远程资源，不继承站点权限；纯文本回退始终可读。
- 搜索仅覆盖当前账户获权成员的发件人、收件人、主题和受限正文投影，分页且有上限；查询失败不得改变或删除源事实。目录计数和分类未读由 `MailboxEntry` 权威事实计算。
- 用户可创建、改名、删除自己的分类并手动指定邮件的单一主分类。删除分类只清除本账户成员视图的分类引用，不移动目录、不改变已读、不影响其他账户。规则和算法建议留到 M4。

### API 与页面

- 浏览器只调用 `mailbox-service` 的已认证 API。Cookie、Origin、CSRF 与撤权语义沿用 M1；所有资源查询以会话账户为 owner 条件，未知与越权统一为 `404 RESOURCE_NOT_FOUND`，版本冲突为 `409 VERSION_CONFLICT`，校验失败为有界 `400`。
- 桌面页面具有固定顶部工具条和三个独立纵向滚动区域。目录栏与邮件列表各自可通过始终可见、键盘可达的按钮独立折叠；恢复后保留当前目录、选择、查询和滚动位置。
- 390px 页面采用目录 → 列表 → 阅读/编辑的逐层路由。浏览器前进/返回保持当前账户的草稿和选择；账户切换或旧请求迟到不得把 A 的响应写入 B 的页面。
- 页面需要真实登录、登出、目录计数、分页列表、阅读、未读切换、归档/垃圾/删除/恢复、搜索、草稿、附件、回复/转发和手动分类。空结果、加载、冲突、存储故障和会话失效提供可行动文字，不只用颜色表示。
- M2 实现最低可用的淡笺纸、墨色、细分隔线和少量朱砂焦点；不增加卡片墙、星标、文件中心或装饰性业务入口。M7 仍负责最终审美精修。

## 预注册用例与失败机制

| ID | 用例与独立预期 | 必需源事实 |
| --- | --- | --- |
| M2-01 | A/B 登录后目录、计数、列表和搜索只出现各自成员视图 | HTTP、SQL owner 行、浏览器 Network/DOM |
| M2-02 | 同一内容可有 A 已读/归档、B 未读/收件箱的独立状态 | 两账户 API 与 `mailbox_entries` 行 |
| M2-03 | 未获权 ID 的读、改、下载和分类均为统一 404 且数据库无副作用 | HTTP 前后 SQL、对象读审计 |
| M2-04 | 草稿创建、更新、重启恢复；旧版本更新得到 409 且不覆盖新内容 | HTTP、版本行、重启后读回 |
| M2-05 | 回复/全部回复/转发生成新草稿，源成员与原 MIME 摘要不变 | API、SQL、raw MIME digest |
| M2-06 | 合法中文 MIME、纯文本、HTML 和中文附件可保存并读回 | raw bytes/hash、派生投影、浏览器 DOM |
| M2-07 | 脚本、事件属性、远图、危险 URL/表单/嵌入内容不能执行或发起网络请求 | sanitizer 单测、CSP、浏览器 Network/DOM |
| M2-08 | 附件越限或路径型文件名有界拒绝；合法附件下载为 attachment 且账户隔离 | HTTP、S3 hash/metadata、浏览器下载响应 |
| M2-09 | 已读、归档、垃圾、删除、恢复只改本账户成员；计数同步 | API、SQL、浏览器红点/计数 |
| M2-10 | 分类创建/改名/删除和人工归类单一生效，删除分类不移动邮件 | API、SQL、浏览器分类计数 |
| M2-11 | 搜索按发件人/主题/受限正文命中、分页稳定；索引/查询故障不损原件 | API、SQL 原件、明确错误 |
| M2-12 | 七入口精确且无额外业务入口；目录栏/列表栏独立折叠，三栏独立滚动 | DOM、键盘操作、同视口截图 |
| M2-13 | 390px 目录→列表→阅读/编辑逐层前进返回，未保存草稿仍在 | 路由、DOM、截图、浏览器状态 |
| M2-14 | A 的延迟响应在登出并登录 B 后被丢弃，页面不显示 A 的正文/附件 | 受控延迟、Network 时序、DOM |
| M2-15 | 写信页面可持久保存 To/CC/BCC、正文和附件，但不宣称发送或 SMTP 成功 | API、SQL、页面明确状态 |
| M2-16 | 服务和依赖正常重启后草稿、成员状态、分类、MIME 与附件仍一致 | owned 启停、SQL/S3/hash、浏览器读回 |

同一机制不按端点、目录和调度排列做无穷组合。上述 16 项是 M2 必过有限分母；发现新的所有权泄漏、原件损坏或对预期的反证时，才增加最小反例并版本化本合同。

## 实现与资源边界

- Mailbox 包保持 `interfaces -> application/domain <- infrastructure`。Domain 不依赖 Spring、JDBC、S3、HTML sanitizer 或 MIME 库；业务状态不进入 `platform-common`。
- 使用版本化 Flyway 迁移，不重写 V1/V2。数据库事实写入继续经过现有 witness/write gate；对象与数据库无跨资源事务，保留 staging、完整引用和确定性清理语义。
- 前端位于 `frontend/web`，锁定依赖并生成生产构建；不使用外部字体、分析、CDN 或远程图片，不把凭据、私人正文或 Cookie 写入构建与公开证据。
- 保持 M1 资源合同 1.1：宿主机总占用连续三次超过 14 GiB、任一业务应用 RSS 超过 384 MiB、容器剩余内存不足 10%、PID 余量不足 16 或 OOM 时立即保留样本并停止 owned 实验。构建、API、浏览器与重启实验串行。
- 单次 API 正文不超过 5 MiB；列表每页最多 100，默认 30；搜索输入最多 200 字符；主题最多 998 UTF-8 字节；地址集合最多 10；分类名最多 40 字符、每账户最多 50 个；草稿附件最多 20 个且合计不超过 4 MiB。

## 资格与退出

先通过项目原生单元/集成测试、依赖锁、类型检查、生产构建和安全负例，再从干净候选创建 fresh owned lab。源事实至少包括：精确源码和构建收据、迁移摘要、两账户 API/SQL、raw MIME 与对象摘要、浏览器 Network/DOM/截图、重启/清理和资源窗口。

项目采集器只规范化事实；VeriTrail Core 使用运行前封存的 Plan 对 M2-01 至 M2-16 给出有限 Verdict。错 source、错账户/消息/对象绑定、缺 MIME 摘要、缺浏览器证据或缺任一必过项必须是 FAIL/INCONCLUSIVE/PENDING，不能 PASS。候选通过后仍需 PR/CI、受保护合入、fresh exact-main 复验和公开状态读回，才可把 M2 标记为 `QUALIFIED` 并进入 M3。
