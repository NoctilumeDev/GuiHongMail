# 归鸿 M0.1 · Go 运行时追加授权

**状态：`APPROVED / PREFLIGHT_REQUIRED` · 2026-10-13。** 本文件追加在原 M0 之后，不改写原 M0、M1 Plan、失败原件或 Java exact-SHA 资格。用户明确允许保留同一 Git 仓库和完整历史，在现有基础上把三个后端服务迁移到 Go；无价值的本地实验目录和远端临时分支可在替代物可审查且身份核对后清理。

## 不变的产品与正确性合同

账户、邮件、SMTP、对象、Outbox、投递 attempt、`UNKNOWN`、取消竞争、服务状态所有权、七入口、M1–M6 有界验收及 M7/E1 停止线全部沿用 M0。语言变化不降低局部事务、幂等、权限、恢复、证据和资源标准，也不把最终一致误写成无一致性要求。

旧 Java 事实按 exact SHA 保留：

- main `f2cd29d6f5943a4025a877b145226a4460338c68` 仍是已公开的 Java M1 资格状态；其 PASS 不授予任何 Go 二进制。
- `baseline/java-m2-candidate-20261013` 指向 Java M2 候选 `3136c6f5df0f53873f798863e37a5c7a97cdafae`。该候选已实现并通过项目原生检查，但尚未取得 M2 VeriTrail、PR、CI、exact-main 资格。
- Go 候选从 M1 重新取证；旧失败和资格仅作为对照与施工经验，不能继承成新运行时结论。

## 新运行时分工

- `mailbox-service`、`smtp-ingress`、`delivery-worker` 使用 Go，保持三个独立进程、schema、凭据和失败生命周期。
- Vue 3 + TypeScript 前端继续使用；可复用的 M2 页面成果必须重新绑定 Go API 和真实浏览器证据。
- Python 只在 M4 出现真实算法训练或推理需要时，通过版本化输入输出合同接入。显式规则留在 Mailbox 域；不得为了语言分工提前增加第四个常驻微服务。
- MySQL 与 SeaweedFS S3 的业务职责不变。消息队列暂不自动替换。

## 首个合法施工门：M1G 兼容预检

全面移植前只允许一个有限预检，避免先写完服务才发现 MQ 路径不成立：

1. 从干净 Go 候选固定工具链、模块依赖与构建输出。
2. 在当前 RocketMQ 5.5.0、NameServer + Broker 拓扑上，用选定且锁定的 Go 客户端实际完成普通持久消息的生产、消费、显式处理确认、内容 hash、重启恢复、精确 topic/group 清理。
3. 同一 watchdog 保存 Broker/NameServer/MySQL/SeaweedFS、Go 探针和宿主机的实际内存、PID、退出与 OOM；14 GiB 宿主停止线及容器余量不放宽。
4. 验证客户端断连、Broker 重启和重复交付时，数据库状态机仍是重试、幂等与投递资格的最终裁决者；MQ ACK 不升级为数据库事务事实。
5. 官方 RocketMQ 5.x Go gRPC SDK 需要额外 Proxy，而当前拓扑没有 Proxy。预检不得悄悄新增 Proxy；若现有 Remoting 路径不满足合同，保留阻断并版本化评估 RabbitMQ，不自行替换 D04。

预检 PASS 只允许开始 Go 的 M1 重建，不等于 M1 或 M2 资格。预检 FAIL/INCONCLUSIVE 时停止全面移植，保留精确客户端、服务端、资源和清理证据，再决定消息队列合同。

## 迁移与清理

Go 重构在 `rewrite/go-runtime` 独立分支和工作树施工。先形成可构建、可审查、可复验的替代物，再删除旧工作树、下载 ZIP、缓存和远端临时分支。Git 提交、tag、main 资格、失败原件和验收摘要不按“残留”删除。Go 候选通过新的 PR/CI、protected merge、fresh exact-main 和产品读回之前，公开状态仍以 Java main 为准。
