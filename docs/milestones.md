## M1–M6 一次授权、逐门推进

用户仅在 M0 定稿及实际开工时授权一次 `M1_START`；这份授权持续覆盖 M1→M6 的原定施工、必要缺陷修复、原合同复验、有限独立审查和工程候选发布。每阶段仍必须有冻结的 Claim、被保护的不变量、exact SHA、自动化与实际证据、失败及停止线。门禁成立后**继续下阶段，不向用户例行索取批准**。

只在以下情况立即停工、留证并申请决定：M0 所有权/邮件语义/部署外网/预算需要改变；外部系统、宿主全局配置或其他仓库将受影响；核心安全/隐私/邮件耐久性发生未能在有限修复中闭合的破坏；环境容量或进程归属不明；验迹/原始事实无法建立而继续施工必须伪造资格。STOP 不等于清空现场或把任务标为完成。

## M5 反例收束，不做无穷 AOP

反例按**不同失败机制**而非 HTTP endpoint × 状态 × 服务 × 时序全部组合计数。优先覆盖：已接受邮件不丢、权限/BCC 不泄露、SendIntent 不重复、SMTP 结果未知可解释、旧 Worker 不倒写、附件/HTML 不执行恶意内容、分类建议不越权；每类挑可独立归因的最小正常/故障/恢复见证。有新机制、高后果新边界、对原证明的反证才扩大实验；同类不同排列已经不提供新增信息时停止扩展。已经观察的核心 Bug 仍必须修复复验，不能用停止规则回避。未试到的条件进 `UNKNOWN/NOT_PROVEN`，附复验入口。

## M6 终止和计时

**计时起点：** 用户授权后的第一个 M1 实际施工动作；**计时终点：** M6 的最后一项预注册退出门成立且工程交付就绪；若阻断则记录阻断时刻而非虚构完成时刻。统一记录 UTC 原始时间与北京时间展示、墙钟时长、自动执行期间、人工介入次数/持续时长、环境阻断、失败与修复次数，以及最后的 Git SHA/Release 身份（可取得则记，没有不填）。这些是**观察量**，不作为验收 KPI；不强迫“三天内完成”，不因此提高并发或放松失败条件。

M6 自动关闭所有本项目 owned 临时实验资源，保存完整清理结果和剩余待用户决定项；Agent 结束会话或报告 `AWAITING_M7_HUMAN_REVIEW`，**不自动优化视觉、不启动 M7、不扩大 E1、也不替用户批准发布产品正式版**。

## E1 · 公网收发（本轮明确不做）

只有用户另行提供并授权真实域名、公网宿主、网络与凭据时，才验证 MX/SPF/DKIM/DMARC、证书、PTR、外部 QQ/Gmail 收发、速率/滥用保护与实际服务商回执。外部 `250` 不证明进入主收件箱，更不能证明已读。
