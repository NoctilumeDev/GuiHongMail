# 归鸿 M0 · 产品定调、工程边界与风险识别

**状态：`M0_CANDIDATE / NOT_SEALED` · 2026-10-13**。这是一份提案，不预先授予任何实现/验证结果。用户确认后才形成冻结版 M0；后续版本只能通过新文档/提交变更，不回写历史标准。

## 1. 目标与验收边界

归鸿不是邮件客户端，也不是 SMTP 协议课堂 Demo；它是本机运行的、具有真实账户与服务器端状态的 Web 邮箱。首轮能让至少两个独立本地账户在同一宿主上**通过真实 SMTP 收发**，用户可以登录、写信、保存草稿、添加附件、回复/转发、整理收件箱、搜索、检查发送状态，关闭/重启后继续使用。Web、SMTP、MySQL 和原始 MIME 均为真实执行，不用截图、内存数组或 mock 冒充产品闭环。

**首轮证明：** Windows 开发机上的受控单宿主、真实 MySQL、持久对象存储、真实 SMTP 连接、失败恢复与浏览器实际使用；本地路由域名 `guihong.test`。**不证明：** 互联网公开收发、可被 Gmail/QQ 自动信任、高可用跨主机、IMAP/POP 客户端生态、无限容量、反垃圾邮件产业级能力、灾难性整机损坏恢复、零漏洞。公网互通可在 E1 单独建立域名/证书/DNS/公网网络资格后推进。

## 2. 产品原则

1. **邮件先是事实，不是界面状态。** 草稿、封存待发内容、SMTP 接受、邮箱成员视图、投递尝试、下一跳接受、回执/退信各有身份。
2. **状态有主人。** 一个事实只有一个最终写入权；服务可读合同，不可夺库。
3. **协议讲真话。** `250 OK` 表示该 SMTP 接收节点承担了本次事务责任；不能直接推断到达最终人的邮箱或已读。
4. **出错可恢复，不擅自补造。** 对结果未知、迟到、重复、故障隔离作出明确语义；首败保留。
5. **单机不降一致性标准。** 允许限制并发/测试规模、明确停止线，不因此允许丢邮件、越权或无穷重试。
6. **现代高效邮箱，汉唐水墨视觉。** 登录可见山水，工作台适合长期收发；不以写意背景遮挡真实操作。
7. **有限工程资格。** 每个里程碑明确已有证据、未证明边界与下个合法施工入口。

## 3. 首轮用户能力（不是可选 Demo）

- 两名以上本地用户、独立账户登录与登出、授权失效/会话隔离；管理员仅能维护受限账户和配置，不得读取用户私信内容当作默认管理权。
- **固定七个基础入口**：写信、收件箱、已发邮件、草稿箱、归档、垃圾邮件、已删除；另有「我的分类」。不预设星标页、文件专区或工作/学习等类别。已删除项可按规则恢复或清理；可从发件人、主题、时间和受限正文文本搜索并分页。
- 邮件列表/阅读/编辑；收件人 To/CC/BCC、回复/全部回复/转发、附件上传/下载、保存和恢复草稿；渲染 `text/plain` 与安全的 HTML/MIME，含中文主题和文件名。目录栏和邮件列表分别可折叠，目录/列表/阅读三个滚动区域相互独立，手机逐层切换且返回保留上下文。
- 真正 SMTP 本地接收与投递、每个 envelope recipient 的独立状态；至少两用户相互发信、回复，断电以外的进程重启后不丢已确认接受的邮件。
- 状态透明：本地已提交、排队、投递中、下一跳 SMTP 接受、暂时失败待重试、永久失败、结果未知；显示可行动的恢复入口。
- 对邮件来源、隐私与容量设限；手工停止/恢复时明确故障，不静默清空发送或收件历史。
- **两阶段分类**：第一阶段用户创建分类、人工归类、建立明确匹配规则；第二阶段用每个用户自己的确认历史训练本地算法，提供可解释建议，经授权才自动分类，保留人工覆盖优先权及撤销。未读红点/计数以服务端事实为准，不代表算法正确率。

## 4. 最小物理架构与服务边界

逻辑上仅三个业务进程（不是三个必须各自部署到不同机器的节点）：

| 角色 | 独占的状态/权限 | 不拥有 |
| --- | --- | --- |
| `mailbox-service` | 身份与会话、账户邮箱视图、草稿与不可变待发送内容、每账户的分类/规则/算法反馈、未读/删除与发送意图 | SMTP 入站接受判定、对外投递尝试真相 |
| `smtp-ingress` | SMTP 会话、收件地址校验、接收后的持久 spool、导入事件与清理义务 | 用户邮件已读/文件夹、外发尝试、Open Relay 权限 |
| `delivery-worker` | 出站 per-recipient 队列、租约/epoch、重试/退信、下一跳 SMTP 会话结果 | 用户身份、邮箱成员视图、收件内容最终所有权 |

三者各有 MySQL schema 和数据库凭据，独立数据库迁移；MinIO 或等价本地持久对象存储承载 MIME 原字节与附件，服务凭据/命名空间隔离。RocketMQ（项目隔离 Topic）传递异步事件；使用本服务事务内 Outbox + 确认/重放，不把 MQ ACK 等同于数据库事务。Web 前端不另造 `web-gateway` 微服务；一个客户端应用消费 `mailbox-service` API。**不建单独认证、搜索、附件或监控微服务。**

如果实现证明某一服务事实上不能独立拥有明确状态或生命周期，应重新评估合并，而不是强行保留三进程以满足数量指标。详见[服务合同](contracts/service-boundaries.md)。

## 5. 高风险义务先写清

- SMTP DATA 最终成功回复之前，必须已耐久保存所接受的完整 envelope + raw MIME；不足条件必须 4xx/5xx 拒绝，不能成功后丢消息。
- 我方发送请求必须先冻结 `message snapshot + envelope recipients + send request identity`，才允许异步投递；同一发送请求重复不会在我方生成两个独立业务发送意图。
- 任意 worker 失败、超时、租约过期、接管或迟到，不能让旧 attempt 无条件覆写新状态；外部 SMTP 重复风险只能说明，不能许诺跨域 exactly-once。
- 收件人可有部分成功与部分失败；To/CC/BCC 与 SMTP envelope 分开，不能把 BCC 泄漏进其他人的头字段或页面。
- 出站下一跳 `250` 仅支持下一跳接受，无法证明最终投递或收件人阅读。
- 删除/移动/已读等用户状态仅修改自己的邮箱成员视图，不能修改另一用户的同源消息状态。
- 原始 HTML 邮件不获得脚本执行、cookie、站内权限或自动加载外部像素的能力；附件不按扩展名信任。
- 下游失败必须有限重试并保存 `UNKNOWN`、永久失败原因及再进入入口。通知、索引、搜索失败不能删除源邮件。

## 6. 风格方向（留在设计合同中实施）

产品名 **归鸿**，取**开元之气、笺纸之雅、水墨之意，以轻为重**。唐风舒展远景，秦汉只取印记与文字骨力；宣纸接近自然白，烟墨远山、流云/流水、长空飞鸿、小面积朱砂。不是日本侘寂、宋式冷寂，也不是厚重宫廷 UI。鸿雁是品牌物种，仙鹤只借其轻盈线条，不用丹顶鹤直接代替。**结构要有，框感要无**，减少卡片/大圆角/硬边框，底角山水退成虚景。桌面三栏，左目录及中邮件列表都可折叠，三个区域独立滚动。参考图保存在 `design/references`，不能照抄偶然生成的文字/星标/错鸟形；真实网页用 HTML/CSS 实现所有可点击控件与文本，图像只作为轻量品牌背景。M7 才由用户参与最终精修，不以“参考图好看”证明功能。

## 7. 工程边界与 STOP

- 单机 Windows 11 优先，以当前可复现的本机环境为准；最低 JDK 17、Node 工具链、MySQL8、真实 SMTP；具体版本和依赖 SHA 到 M1 选型/锁定，不事先捏造测试证据。
- 每轮先记录 CPU/内存/磁盘/端口/容器/网络代理现状与资源归属；容器按需启动、验证串行、并发只由有界故障用例引入，不跨项目共享库。16 GiB 参考机超过 14 GiB 观测停止线持续时保存状态并停止，本机容量不同则 M1 以实测预算冻结，不扩大物理限制。
- 禁止修改宿主代理、系统网络策略、Docker daemon、其他项目数据库或全局环境；未知监听者一律不接管。清理仅针对 `guihong-*` 精确归属的本次资源。
- 本地模拟/私有邮件绝不发布原文；公开证据必须是合成账户、脱敏摘要与独立原件 hash。
- 触发未授权转发、跨用户私信泄露、提交后已接受邮件丢失、伪造成功、无界资源消耗、安全边界突破时停止发布；失败归类并保留原迹。
