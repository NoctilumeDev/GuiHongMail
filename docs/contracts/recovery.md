# 旧快照恢复与投递隔离合同 1.0

恢复旧 MySQL/对象存储快照不会回滚 SMTP 下一跳已经接受的邮件，也不会回滚用户已看到的回执。M6 的真实数据库恢复门必须区别于同一数据的进程重启。

## 每服务自己的恢复坐标

各服务维护独立 generation、持久数据库事务 marker 与数据库/对象恢复目录之外的有界追加事务见证账册。业务记录与 marker 在同一数据库事务中提交；提交前耐久 PREPARE，确定提交/回滚后追加相应结果。提交结果未知或提交后回调失败不能推定回滚；原 PREPARE 保留。账册不含秘密或私信，独占归属/文件锁，链摘要、格式、容量、IO 预算及只增历史可验证。

账册不取得邮件状态所有权；它只提供本服务已向外发布或可能发布事实的恢复见证。不能把三服务并成全局事务或用共享账册签发跨服务业务成功。具体端口/格式在 M1/M3 进入前预封存，与 marker 的真实原子性需实际验证。

## NOT_RECONCILED

已知 COMMIT marker 丢失、账册/marker 代不一致、未知 PREPARE 无法核对、账册缺失/损坏、对象引用与存储不一致、恢复源不属于本代，均进入明确 `NOT_RECONCILED`。停止业务写、投递领取、重试、导入、Outbox 推進和 GC，健康接口明确未就绪；查询不能用旧库空结果解释为当前没有邮件或允许新发送。

已有 generation 时不能自动初始化新账册、裁剪历史、换请求键或自动重投绕过隔离。解除需恢复一致坐标或提供具名、可审阅的人工处置；不能设置网页强制继续按钮。临时 DB 读取失败不等于不存在 marker。

## 有限验收

正常同数据进程重启保持原 SendIntent/回执；T0 备份后通过真实 SMTP 形成新接纳/回执，保存独立下一跳见证，再恢复 T0，必须隔离且不重复投递。另用当前数据正常控制后仅移除账册，验证隔离；不能混入额外旧库回退。涉及跨服务时只增加能破坏既有义务的必要错代交接，不穷举三库所有排列。

只在 owned 实例/目录/端口做恢复，宿主既有数据库和其他项目不动。首次空项目可初始化；已有状态不得隐式采纳。完整宿主和全部见证一起回退、物理掉电、恶意特权篡改、跨主机灾备仍未证明，不用于回避上述必过门。
