# 安全、隐私与滥用边界合同 0.1

**M0 approved — SEAL_PENDING / NOT IMPLEMENTED**。单机是部署限定，不是删除安全义务的理由。

## 核心资产与权限

账户凭证、会话、每账户邮件和附件、SMTP 原始字节、收/发地址、Bcc、投递日志、配额、API 与 SMTP 网络能力均需按最小权限保护。Web、SMTP 和异步事件的身份不等价；匿名 SMTP 发信不得自行取得 mailbox 用户的读取权。管理员能维护账户与运行状况，**默认不能读取任何用户邮件正文、附件或 BCC**。

## 必须从 M1 起生效的界限

- 凭证用适合的密码哈希算法；随机会话，HttpOnly、SameSite、CSRF 与 Origin 校验；登录速率限制；不把账户是否存在暴露给未认证方；退登/撤权对新操作生效。
- 本地演示通过 loopback 或隔离网络访问；公网访问时必须先 TLS、认证与部署安全合同，M0–M6 不允许裸露开发 SMTP 端口到互联网。
- SMTP 入站仅指定本地域，明确拒绝 open relay；若未来启用外部客户端 Submission，强制经过 TLS 与 AUTH/明确独立授权，不能套用未认证的 MTA 接收策略。[RFC 8314](https://www.rfc-editor.org/info/rfc8314/) 提供提交/访问 TLS 参照。
- 收信展示永不直接信任 HTML/MIME：清理脚本、事件处理器、危险链接、CSS/属性，隔离 HTML 预览，默认不自动加载远程图像/跟踪像素。纯文本回退、外链提示，不自动执行附件。
- MIME/消息头防 CRLF 注入、畸形编码、递归 multipart、附件炸弹、任意路径/文件名逃逸；有界字节/层级/parts、解析 CPU/内存与超时。附件访问必须再核对每用户所有权和安全下载策略。
- `Bcc`、密件内容、令牌、Cookie、数据库口令和原始私人邮件不进入公开 Evidence、浏览器控制台、CI Artifact 或 Git 历史；日志只保留最小元信息和脱敏相关 ID。
- 分类学习默认仅在本机/当前账号域内处理用户已确认的归类样本；不把个人正文/通讯录发给外部 LLM 或其他用户模型。规则、建议、人工覆盖和自动采纳的版本/权限各有可追踪依据，分类算法无独立的邮件删除/发送权。
- 备份/恢复不能通过恢复旧数据库覆盖后来外部已经接受的投递事实；外部不可回滚的事实须单独对账并保留不确定性。

## 执行/资源隔离

- 每服务独立 MySQL 用户/schema，SeaweedFS S3 前缀/桶和账户隔离，MQ Topic/Group 项目前缀。业务测试使用项目独立 fixture，用户发信与真实外部邮箱默认不能进入测试。
- 设定每账户总存储/请求/收件人/附件/邮件大小/每日提交/重试预算，实际数值在 M1 测量后冻结；超限有明确错误与恢复路径，不触发无界内存缓冲。
- 压测、丢包、断连只在项目拥有的模拟下一跳/代理链执行。严禁修改系统代理、VPN、Docker 全局配置或杀死未知服务。
- 队列堆积/延迟、失联 ingress、spool orphan、投递 `UNKNOWN`、长期重试、被动攻击拒绝次数和容量接近停止线应可观测；不要求为此拆独立可观测微服务。

## 不宣称

不宣称端到端加密、企业邮件合规、恶意附件完全检测、反垃圾邮件产能、公网信誉、绝对匿名、抗所有攻击，亦不把本地单宿主存储视为灾备。以上都需要各自独立的威胁模型和验收证据。
