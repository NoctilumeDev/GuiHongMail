# SeaweedFS、接纳与对象清理合同 1.0

首轮采用 SeaweedFS 单宿主 S3，不部署分布式集群。M1 固定版本、OCI 镜像摘要、配置及运行资产摘要；业务只依赖标准 S3 存储端口。版本锁定及接口可用不等于取得持久化资格。

## 命名空间与访问

Mailbox、Ingress、Delivery 使用独立凭据和必要权限。MIME/附件归所属服务 bucket/namespace；其他服务通过具名认证读 API 或有界短期内容能力取内容，不能获得源桶管理权。SeaweedFS 的非 S3 管理/存储入口仅在受控内部网络可达，不能利用后端 HTTP 绕过 S3 认证。匿名与跨服务读写删均需真实拒绝见证。

## 对象与数据库交接

不可变对象先写 staging，保存 owner/run/source id、hash、size、创建身份和状态；真实 GET 核对内容后才允许数据库事务保存完整引用。对象 PUT 和数据库 COMMIT 不构成跨资源事务。

| 观察 | 处置 |
| --- | --- |
| PUT 失败或结果未知 | 不创建已确认引用；核对同一对象坐标，不换键伪造成功 |
| PUT/GET 成功，DB 确定回滚 | 保留归属，满足无引用与无在途条件后 GC |
| DB COMMIT 结果未知 | 禁止因查询失败/超时推断无引用；保留并对账 |
| 已提交引用，对象不可读/损坏 | 明确存储故障，保留原事实和摘要，不返回空邮件或成功 |
| 导入提交，确认事件丢失 | 原导入回执幂等重放，不能重复成员视图 |

Mailbox 导入先在自己的空间持久保存并验 raw MIME/附件，再以同一事务写 source receipt + 每 recipient 的 MailboxEntry + 完整对象引用 + 导入确认 Outbox。Ingress 只有取得匹配 spool/source/recipient/hash 的持久导入确认后，才解除该 recipient 的保留义务；不能以 MQ ACK、HTTP 已返回、目录不存在或时间到期替代确认。无跨服务 JOIN/共享可变 blob。

Mailbox 的共享内容引用计数或引用集合由本服务事务维护。删 A 的成员视图不影响 B；有收件、草稿、发送快照或仍在途的授权引用时不物理删除。GC 只处理具名 owner 的无引用对象，有界扫描/批次/时间及重入收据；年龄仅作为宽限条件，不能单独证明无引用。检查不可用、COMMIT 未知、导入待定或恢复未对账时不清理。

## SMTP 接受与准入

Ingress 在 DATA 最终成功回复前必须耐久保存完整 envelope、raw MIME、实际接受 recipient 集合及责任记录。未耐久时拒绝，不在明确 4xx/5xx 后继续导入该未接受事务。支持的首轮协议 profile 在 M3 前封存：ASCII 本地域 envelope、UTF-8 中文 MIME/文件名、严格 DATA/CRLF/dot-stuffing、有界 SIZE/RCPT/parts/时限，只宣告真实支持的扩展；不宣称 SMTPUTF8/全部互联网扩展。

有效账户和额度由 Mailbox 所有。Ingress 在接受前取得具名、版本化的 recipient admission/额度保留，绑定不可复用账户 id 与本次接收身份；保留、消耗、释放幂等。离线/额度不足且无法承担责任时在接受前明确临时或永久拒绝。停用账户拒绝新准入，不撤销已经持久接纳的责任；首轮不硬删除或回收仍有接纳责任的账户地址。

已接受后的暂时导入故障有限重试；到限/永久失败进入明确受控异常或退信流程，原 spool/责任记录在完成投递、持久通知义务或明确授权处置前不删除。需要通知时用真实 envelope reverse-path，不能用可伪造的 From 头替代；退信使用空 reverse-path，不能对空 reverse-path 再生成退信。首轮只路由受控本域/测试下一跳；外域通知义务不能偷偷越过 E1，由准入限定避免承担未授权责任并保留明确异常。

## M1 存储资格

真实 PUT/GET/DELETE；重启数据仍存在；三凭据及匿名越权拒绝；数据库元数据与对象写入/提交故障窗口；在途/有引用对象不误删、可归属孤儿可重入清理；恢复对账、单机资源预算。各类有正常对照与独立观察。失败保留原件并阻断，不换存储或降标准。
