# 邮件事实与 SMTP 可靠性合同 0.1

**M0 draft — NOT IMPLEMENTED**。以 [RFC 5321](https://www.rfc-editor.org/info/rfc5321/)、[RFC 5322](https://www.rfc-editor.org/info/rfc5322/)、[RFC 6409](https://www.rfc-editor.org/info/rfc6409/) 及 MIME 相关 RFC 为行为参照；选择经维护的 SMTP/MIME 实现库，不自造不完整协议解释器。

## 事实拆分

| 名称 | 权威 | 不能冒充 |
| --- | --- | --- |
| `Draft`（可变） | Mailbox | 已发送内容；草稿保存成功不能视为投递成功 |
| `ImmutableMessage` / envelope | Mailbox（发）、Ingress（收件 spool） | UI 的当前编辑正文；头部 To/CC/BCC ≠ envelope 的 RCPT 集合 |
| `SendIntent` + receipt | Mailbox | 外部 SMTP 已接受、已读 |
| `IngressAcceptance` | Ingress | 已进入目标用户收件箱、对方已阅读 |
| `MailboxEntry` | Mailbox 每账户 | 另一账户的已读/删除/标签 |
| `DeliveryAttempt/Outcome` | Delivery | 接收人的最终收取或已读事实 |
| `Bounce/DSN observation` | 归属的实际接收/传输者 | 可凭猜测写成投递成功 |

## 用户提交与草稿

- 草稿有版本号；编辑并发采用显式乐观版本校验。发送必须冻结收件地址快照、标题、正文、附件、MIME 规范字节、身份、`client_request_key` 与规范化 payload hash；同 key/同身份/同正文重放只返回同一个 `SendIntent`；异正文必须冲突而非覆盖。
- 发件的 UI 收据 `SUBMITTED_LOCAL` 只说明本服务已接纳且持久化，不能生成 `DELIVERED`。一封发件可有多个 RCPT，每个 recipient 独立状态；部分失败不删除其他收件人的已完成结果。
- BCC 只出现于授权发件人编辑/已发送视图；不泄露到发给 To/CC 或其他 BCC 的可见头部。收件转发需保证私有地址和原头部经明确用户操作处理。
- Message-ID 可用于会话和参考，但不被假设为全世界可信、唯一或不可伪造的幂等键。内部 idempotency 用版本化业务/attempt key。

## 入站 SMTP 的边界

- 收件人域和收件人身份有 allowlist；`RCPT TO` 不可把域外地址开放为匿名中继。大小上限、RCPT 上限、时限、行结束、MIME 数量/深度、连接数与缓冲限额在执行前生效。
- `DATA` 完整接收后，对 sender/envelope/raw MIME 生成可验证 spool 原始字节，落存储且数据库持久化成功才能回复最终 `250`。如果未持久化或无权负责后续投递，必须拒绝并留受控错误。
- 接受后导入 mailbox 可异步重试；断电以外的进程中断不能静默丢失已接受 spool。`250` 回复丢失时发送方可能重试；跨独立 MTA 的物理 exactly-once **不承诺**。在本系统拥有的 ingress→mailbox 交接中使用 source receipt / recipient 标识保证逻辑效果幂等。
- 入站解析必须保留原始 RFC5322/MIME 字节，派生安全展示投影，不能因为无法解析 HTML 或未知编码而改写原件。不可安全解析时拒收或收件隔离，由合同固定边界，不伪造正常正文。

## 出站 SMTP 的边界

- `DeliveryJob` 仅从已持久化的 `SendIntent` 幂等产生。领取时记录 attempt ID、lease、epoch/fence 和实际 worker；超期旧实例不能修改本地终态或把新投递结果倒退。
- SMTP `4xx` 可按带上限的重试策略延迟，`5xx` 按具体 RCPT/DATA 语义永久失败或策略明确需人工审查；不同收件人的结果独立。
- `250` 接受表示**下一跳 SMTP**在本次会话中承担责任，不表示最终投递、更不表示阅读。收到正答但本地记录前崩溃，恢复要保留 `UNKNOWN` 或采用明确的至少一次再尝试政策并披露重复风险；**fencing 只能防本地过期写，不能撤销已经发给外部 SMTP 的命令。**
- 自己的收件箱最终以 MailboxEntry / 事实导入为准；“已发送”与“下一跳接受”分离；远程 bounce/DSN 是后续观察，不是原响应的天然延伸。

## 邮箱成员视图

一个 raw message 对不同账户拥有不同 `MailboxEntry`。`READ`、`CATEGORY_ASSIGNED`、`ARCHIVED`、`SPAM`、`TRASHED`、恢复与永久清理是成员状态，不是修改原始 MIME。物理清理须满足所有引用/保留与安全策略；删除者不能影响其他账户。线程/搜索/未读计数是投影，错误或陈旧时明确降级和重建；禁止投影写回原始事实。

## 用户自定义分类与算法建议

- 初始只有用户的分类集合，不默认创建「工作/学习/生活」之类的标签；允许用户显式命名/改名/删除，并指定对同一邮件的人工分类。初版采用**单一主分类**语义，系统目录（收件箱/已发送/归档/垃圾邮件/已删除）是不同于个人分类的维度；移入某分类不能偷偷改变邮箱收件/已读/删除状态。
- 第一阶段确定性规则：仅对当前账户允许的发件人、域名、主题关键词等字段检查；规则版本、优先级与命中证据可复算，不跨用户提取私人样本。人工明确锁定的类目优先于规则；分类更新、恢复、删除与审计在 Mailbox 本地事务中完成。
- 第二阶段算法只消费当前用户已确认的归类历史与脱敏特征（M4 决定固定算法和训练预算），独立保留训练与推理版本、样本规模、置信/未知、建议原因与反馈；不能把置信分数当最终真实性。默认仅建议，用户可按类目或规则**明确开启**自动采纳且可关闭/撤销；人工覆盖后不会被后台重训反向改回。
- 冷启动、历史不足、同类冲突、意图不明或模型不可用时退回人工/显式规则；不以未经用户许可的第三方大模型访问私人邮件。系统未读红点由 MailboxEntry 独立计算，任何算法错误不得伪造已读或移动邮件到垃圾箱。

## 外部互通资格是另外一项工程

真正向 QQ/Gmail 之类外部系统发信，需要可控域名、MX / SPF / DKIM / DMARC / DNS 反解、TLS、公网路由和服务商策略等额外条件；即使外部 MX 回复 SMTP `250`，仍不能保证落在对方主收件箱。M0–M6 只承诺受控本机/隔离下一跳真实 SMTP 验证，E1 另行批准后再谈公网域名与可送达性。
